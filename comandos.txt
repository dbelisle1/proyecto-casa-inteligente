COMANDOS PARA REINICIALIZAR Y ARRANCAR EL PROYECTO
=================================================

Ejecutar los comandos en PowerShell desde la carpeta raiz del proyecto.

Reinicializacion completa de las dependencias
---------------------------------------------

1. Eliminar el entorno virtual anterior:

Remove-Item -LiteralPath .\.venv -Recurse -Force -ErrorAction SilentlyContinue

2. Crear un entorno virtual nuevo con Python:

python -m venv .venv

3. Actualizar pip dentro del entorno virtual:

& .\.venv\Scripts\python.exe -m pip install --upgrade pip

4. Instalar las dependencias del proyecto:

& .\.venv\Scripts\python.exe -m pip install -r .\requirements.txt

5. Arrancar la interfaz:

& .\.venv\Scripts\python.exe .\app.py


ARRANQUES POSTERIORES
=====================

Si el entorno .venv ya existe y funciona, arrancar directamente con:

& .\.venv\Scripts\python.exe .\app.py

Tambien se puede instalar/verificar dependencias y arrancar mediante el script:

powershell -ExecutionPolicy Bypass -File .\iniciar.ps1


PRUEBAS AUTOMATIZADAS
=====================

& .\.venv\Scripts\python.exe -m unittest -v


NOTA SOBRE ARDUINO
==================

Antes de usar la interfaz, cargar en el Arduino UNO el sketch:

.\arduino\ControlLedUno\ControlLedUno.ino

El sketch requiere instalar "RTClib by Adafruit" desde el gestor de
bibliotecas de Arduino IDE. Conectar el DS3231 de esta forma:

SDA -> A4
SCL -> A5
VCC -> 5V
GND -> GND

Para el servomotor:

Señal -> D2
VCC -> fuente regulada de 5V adecuada para el servo
GND -> GND compartido con el Arduino

El sketch también utiliza la biblioteca oficial "Servo". Si Arduino IDE no la
encuentra al compilar, instalarla desde el gestor de bibliotecas.

Posición abierta -> 89 grados
Posición cerrada -> 0 grados

Para el módulo L298N y el motor DC:

IN1 -> D3
IN2 -> D4
OUT1/OUT2 -> terminales del motor
ENA -> jumper de habilitación colocado
GND de la fuente del motor -> GND del Arduino

Usar una fuente externa adecuada para el motor. El tiempo de recorrido se
calibra con kQuarterTravelMs en el sketch; su valor actual es 50 ms. La
potencia se limita aproximadamente al 15% mediante PWM por software. Ajustar
kPoweredTimeUs si el motor necesita más o menos velocidad, manteniendo
kPwmPeriodUs en un valor mayor que kPoweredTimeUs.

Para el sensor DHT11 (requiere "DHT sensor library by Adafruit" y
"Adafruit Unified Sensor"):

DATA -> D5
VCC -> 5V
GND -> GND

Si se usa el sensor DHT11 suelto y no un módulo, conectar una resistencia
pull-up de 10 kΩ entre DATA y 5V.

Para el sistema de alarma:

Señal o SIG del buzzer -> D6
OUT del sensor PIR -> D7
VCC -> voltaje indicado por cada módulo (normalmente 5V para el PIR)
GND -> GND compartido con el Arduino

El firmware usa tone() con 440 y 523 Hz, pensado para un buzzer pasivo. Si el
buzzer consume más corriente que la permitida por un pin del Arduino, usar un
transistor o un módulo buzzer con entrada de señal. Cada detección produce cinco
segundos de sonido; desactivar la alarma interrumpe el buzzer inmediatamente.

Para la iluminación automática controlada por la alarma:

Ánodo del LED -> resistencia de 220 a 330 ohmios -> D9
Cátodo del LED -> GND
5V -> fotoresistencia LDR -> A0
A0 -> resistencia fija de aproximadamente 10 kohmios -> GND

Con este divisor la lectura disminuye al oscurecer. El LED se enciende con una
lectura menor que 500; el umbral se
configura con kDarkThreshold en el sketch. El LED siempre permanece apagado si
la alarma está desactivada.

Luego cerrar el Monitor Serial y el Serial Plotter de Arduino IDE para dejar
libre el puerto USB.
